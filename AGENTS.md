# Code — Competitive Programming Solutions

Competitive programming solutions, one standalone file per problem. C++17 primary (`g++ -std=c++17 -O2`), occasional Python. Ships a Node.js progress dashboard — frontend split into `index.html` (结构 + 防闪烁主题 inline script), `style.css`, `app.js`, served by `server.js` with SSE live-reload. No build system, no tests, no lint/CI — verification means compiling and running by hand.

## Layout

- Contest platforms: `AtCoder/` (→ `AtCoder Beginner Contest/`), `CodeForces/` (`Div. 2/`, `Div. 3/`, `Educational/`, `GYM/`), `HDU/` (一年一个 `2026“钉耙编程”中国大学生算法设计暑期联赛/`), `NowCoder/` (groups incl. `2025/2026牛客暑期多校训练营/`, `牛客周赛/`, `牛客练习赛/`, `牛客小白月赛/`, `高校比赛/`), `XCPC/` (ICPC/CCPC 现场赛与线上赛，9 个比赛，如 `XCPC/The 2022 ICPC Asia Xi’an Regional Contest/`). Nesting is `Platform/group/contest/`; XCPC contest dirs sit **flat** under `XCPC/` (`Platform/contest/`).
- `算法课程设计/` — 顶层课程作业，子目录为一场 vjudge/qoj 比赛（见下方 `course` 扫描规则）。
- `LuoGu/` — topic chapters (算法竞赛进阶指南， 串串， 分块， 莫队， SA， STD， 数论基础， 树链剖分， 浅谈网络流， 网络流与线性规划), arbitrary depth.
- `Template/` — markdown docs for the personal C++ template (`00-模板骨架`/`01-数据结构`/`02-图论`/`03-数学`/`04-字符串`); `00-模板骨架.md` is the canonical skeleton reference and mirrors `ihxnan.hpp`. `Template/md2pdf.py` renders them to `Template/pdf/*.pdf` + merged `pdf/ACM模板合集.pdf` (needs pandoc, chromium, pdftotext, python `pypdf` + `reportlab` — all present on this machine).
- Repo root also holds the dashboard frontend (`index.html`, `style.css`, `app.js`, `favicon.svg`) and `docs/编辑功能设计.md`.
- `vendor/` — 前端第三方依赖的本地副本（**页面不访问任何 CDN**，离线可用、首屏不等第三方）：`vendor/hljs/`（highlight.js 11.9.0 core + cpp/python 语言包 + github 亮/暗主题 css）、`vendor/marked/`（marked 12.0.2）、`vendor/codemirror/`（5.65.16 core + 6 个 mode + 3 个 addon，`--edit` 下点「编辑」时懒加载）、`vendor/fonts/fraunces.{css}` + `fraunces-0*.woff2`（Fraunces 600/700 的 latin 子集）。**中文 serif 不 vendor**（Google Fonts 把它切成 104 个 woff2 分片），改用系统 `Noto Serif CJK SC`，已写进 `style.css` 的 `--serif` 链。升级这些库时手工替换文件即可。
- `Downloads/` — 分发用的安装包（**tracked**，8 个文件 ~679MB）。不是比赛平台，但 `scanDownloads()` 会把它扫成 `data.downloads`，在页面「资源」板块的「文件下载」子组里列出，每个文件一个下载按钮。
- `.reasonix/` is tooling state, not part of the repo.
- A **contest dir** = any dir containing `.cpp`/`.py` files or `.config.json`; anything else is recursed into.
- Scratch/aux files live alongside solutions (`ans.cpp`, `data.cpp`, `diff_*.txt`, extensionless ELF binaries); some folders have `.vscode/tasks.json`.
- `sync.sh` runs `server sync …` — the `server` command is not shipped here; likely stale, don't rely on it.

## The `ihxnan` header (critical for compiling)

- `#include <ihxnan>` resolves via symlink `/usr/local/include/ihxnan` → `~/Github/Template/Template/ihxnan.hpp` (a different repo, outside this one). Solutions compile out of the box on this machine.
- The header itself includes `bits/stdc++.h` and defines: `endl` → `'\n'`, typedefs (`ll`, `ul`, `lll`, `vi/vvl`, `pii/pll`, `ti/tl`, …), constants (`iINF`, `lINF`, `mod=998244353`, `MOD=1000000007`, all `const ll` — can't reassign), segment-tree/block macros (`ls/rs/bl/bi/br/fid/gx/gy`), `rd0(x)` (whole container) / `rd1(x)` (from `x[1]`, 1-indexed), and **built-in multi-test**: global `int t=1` + `int main(){while(t--)solve();}`.
- Multi-test: read `t` at the top of `solve()` (or a global initializer like `int init = [] { return cin >> t, 0; }();`). The `// #define MULTIT` line in the INCLUDE banner is a **dead VSCode-snippet placeholder** (snippet `acm` from `~/Github/Template/Template/cpp.json` — in the header repo, not here) — the header defines no `MULTIT` and nothing reads it; uncommenting it changes nothing.
- Default build: `cin`/`cout` are macro'd to a fast-IO struct (`fin`/`fout`) that supports **integers, char, string only** — `double` fails at compile time, don't mix in `printf` (buffer flushes in the destructor).
- `-DIHXNAN` enables debug mode: includes `<dbg>`, keeps real std `cin`/`cout`, activates `gdb()`, `gdbif()`, `gdb_assert()`, `TIME()`. It **requires `-std=c++20`** (`dbg.hpp` uses `source_location`; `-std=c++17 -DIHXNAN` fails to compile). In submit mode only `gdb()`/`TIME()` degrade to no-ops — `gdbif()`/`gdb_assert()` are undefined and **break the build**, so wrap them in `#ifdef IHXNAN` or delete before submitting. 9 files `#include <dbg>` unconditionally → those also only compile with `-std=c++20`.

## Commands

- Compile & run: `g++ -std=c++17 -O2 -o /tmp/x A.cpp && /tmp/x < input.txt` — this is the submit-equivalent build; add `-std=c++20 -DIHXNAN` for debug builds (both flags together; C++20 is required by `<dbg>`).
- Python: `python3 A.py < input.txt`
- Template PDFs: `python3 Template/md2pdf.py` (from repo root; writes `Template/pdf/`).
- Dashboard: `node server.js [port]` (default 3000) — prints `✓ Ihxnan 面板已启动: http://localhost:<port>`; `GET /` → 200, `GET /api/data` → JSON. Design doc: `docs/编辑功能设计.md`.
  - File watching: only a `server.js` change restarts the server process; `.js`/`.css`/`.html`/`.json`/`.cpp`/`.py`/`.md` changes invalidate the `/api/data` cache and push an SSE `reload` (browser re-fetches `style.css`/`app.js`). `.git/`、`.reasonix/`（每次工具调用都会写 `snapshot.json`，而 `.json` 在白名单里）与 `node_modules` 下的变动被显式忽略——否则页面会被无关写入反复刷新。
  - Endpoints: `/api/data` (contest stats, cached), `/api/code?dir=…&problem=…` (source view, `.cpp`/`.py` only, path must stay under repo root; also returns `full` = the inlined submission-ready file), `/api/events` (SSE), `/api/capabilities` → `{"edit":<bool>}`, `/api/file?path=` (GET read with `mtime`/`writable`; PUT/POST write). Static files decode the URI and are jailed under the repo root (403 on escape); Chinese filenames work, and they are served via `fs.stat` + `createReadStream` with `Range` support (206 + `Content-Range`, suffix `bytes=-N`, 416 on unsatisfiable) — that's how 大文件如 `/Downloads/*.exe` 可断点续传/边下边看.
  - **网页编辑**: `node server.js --edit` 才开启写接口（且仅限本机回环；服务器部署不带 `--edit` 即纯只读）。可写区域：非 `Template/` 的 `.cpp/.py` 题解、`Template/*.md`、任意 `.config.json`；页面资源与 `server.js/sync.sh`/`AGENTS.md` 等只读。PUT 带 `baseMtime` 乐观锁（不符 → 409，`null` = 强制覆盖）；POST 用于新建（题解 `.cpp/.py` 与 `.config.json`，已存在 → 409）。前端在代码/模板查看 modal 内「编辑」进入 CodeMirror（懒加载自 `/vendor/codemirror/`，无 CDN）；未解决题 hover「+」新建题解；`.config.json` 走 contest 卡 ⚙ 表单（无 config 时即新建）。
  - `/api/code` also returns `full`: a **submission-ready** single file produced by `inlineTemplates()` — any non-std `#include <x>` that exists under `/usr/local/include/` is expanded (non-recursively), and Python `from ihxnan import *` is expanded from `~/Github/Template/Template/ihxnan.py`. The frontend's copy button copies `full`, so pasted code is self-contained.
  - **Verifying a dashboard change (there is no test suite)** — `node server.js --edit`, then check the JSON instead of clicking through: `curl -s localhost:3000/api/data | python3 -c "import json,sys;d=json.load(sys.stdin);print({k:(len(v) if isinstance(v,list) else v) for k,v in d.items()})"` for scanning, `curl -s 'localhost:3000/api/code?dir=<dir>&problem=A'` for `full` inlining, and `curl -s 'localhost:3000/api/file?path=<rel>'` for the read/write whitelist. Before/after any nav edit, measure `.nav-links` `scrollWidth - clientWidth` in devtools. SSE `reload` means a browser refresh isn't needed after a `.cpp`/`.json` change, but a `server.js` edit restarts the process (see below).

## Dashboard architecture (server.js / app.js / index.html)

- **Zero dependencies**: `server.js` `require`s only `http`/`fs`/`path`/`child_process` (125–128) — no express, no `node_modules`, which is why there is no `package.json`. The whole router is one `http.createServer` callback with an if-chain on `url.pathname`, in order: `/api/capabilities` (736) → `/api/events` SSE (744) → `/api/data` (759) → `/api/code` (820) → `/api/file` GET/PUT/POST (893/932/1020) → static-with-`Range` fallthrough. `index.html` loads `app.js`/`style.css` with plain tags: no bundler, no ES modules.
- **The self-restart re-spawns with its own argv** (`server.js:1216`: `spawn(process.argv[0], process.argv.slice(1), {stdio:'inherit'})`), so `--edit` and an explicit port survive an edit to `server.js`. Flag parsing is `EDIT_ENABLED = argv.includes('--edit')` (571) and `PORT` = first all-numeric argv else 3000 (572–575).
- **Writes are atomic and body-limited**: `atomicWrite()` (719) writes `<file>.<pid>.tmp` then `renameSync`s over the target, so an interrupted or failed save cannot leave a truncated solution; `readBody(req, limit)` (700) destroys the request once the body exceeds the limit.
- **`app.js` is a single IIFE** — every function is an inner (hoisted) declaration, nothing is exported and there are no globals. Shared mutable state lives in IIFE-level `let`s declared at various points (not grouped at the top): `lastData` (2), `ctDir` (972), `EDITABLE` (1084), `codeShare` (554), `codeCopyText`/`codeInlined` (568–569). "Adding a handler" means adding an inner function declaration here, not a module.
- **Client persistence**: `localStorage['ui.theme']` is written by `app.js` `storedTheme()`/`applyTheme()` (1770–1791) **and** read by `index.html`'s anti-flash inline script before first paint — the two must stay in sync, or the theme will flash. Collapse state uses `localStorage['ui.collapse.<key>']` (246/255).
- **`docs/编辑功能设计.md` is the source of truth for the write path** (deployment model, the exact writable whitelist, the API contract, 409 semantics); `server.js:667` cites it. Read it before touching `/api/file` or the edit UI rather than re-deriving the rules from the code.

## Dashboard scanning rules (server.js)

- `/api/data` = `scanPlatform()` over AtCoder, CodeForces, HDU, NowCoder, **XCPC**, **算法课程设计** (`course` — 顶层 `算法课程设计/`，每子目录是一场 vjudge/qoj 比赛，题目文件名形如 `A Quoit Design.cpp`，该平台 `getSolved` 走 loose 模式取首段作题号), plus `scanLuogu()` (章节树，`scanChapters(baseRel, makeUrl)` 共用) and `scanTemplate()` (`Template/*.md` in a separate docs section `data.template` — markdown view + download, not counted in stats), and `scanDownloads()` (`Downloads/` 下每个非隐藏文件 → `data.downloads` 的 `{name,file,size,mtime}`，按 mtime 新→旧；同样不计入 stats). There are **no** top-level `QOJ/`/`Vjudge/` folders: qoj.ac / vjudge.net rounds surface as `XCPC/` or `算法课程设计/` contests (题目链接由 `problemUrlByHost` 按 config.url 域名分发).
- XCPC problem-link builder (`xcpc` in server.js) dispatches by the hostname of `config.url`: `qoj.ac` → `${url}/problem/{id}`, `vjudge.net` → `${url}#problem/{id}`, any other host → no link.
- Solved-file recognition (`getSolved`): stem must match `^[A-Z]$`, numeric `1`–`20`, or `^[A-Z]\d+$` (C1, P10446). Lowercase stems, numbers > 20, mixed names (`8a.cpp`, `-C.cpp`), dotfiles, and extensionless files are ignored. Dedupe by stem.
- **LuoGu exception**: `scanLuogu()` uses raw filenames with no pattern check — titled names like `P3370 【模板】字符串哈希.cpp` count there, but the same style in a contest dir would be invisible. Problem links truncate the stem at the first `.` or space (`P3379 【模板】….cpp` → link `P3379`); display and `/api/code` still use the full stem.
- `.config.json` per contest: `{"url": "…", "cnt": <total>}`. `cnt` always beats the per-platform `DEFAULT_TOTAL` fallbacks (AtCoder default 7; CF `Div.1 + Div.2` 9, `Div.2` 6, default 7; HDU 暑期联赛 13 else 10; NowCoder 周赛/练习赛 6, `2025牛客暑期多校训练营` 12, default 6). **XCPC has no `DEFAULT_TOTAL` rules** (`getTotal` returns null) → rounds rely entirely on `cnt`. Both keys matter — a typo'd key (e.g. `"ur"`) silently drops problem links.
- Keyword matching pitfalls: `'Div.2'` never matches "Div. 2" (space) folder names → CF falls back to 7; `'2025牛客暑期多校训练营'` does **not** match 2026 camps → they depend entirely on `.config.json`.
- Display ids: letters A, B, C…; solved variants like C1/C2 expand that letter in place. HDU shows numeric `1..cnt` and builds problem URLs as `pid = 1000 + id` from the `cid` query param of `config.url`.
- `index.html` groups contests by the first subdirectory under the platform (`renderContestList()`), sorted by name, ungrouped contests last. nav/section 配对是 `atcoder…course` + `section-resources` —— 后者把「模板文档」「文件下载」并成**一个**板块（内部两个 `.res-group`，各带 `.res-sub` 子标题 + `rescount-*` 徽标），这样 nav 只有 8 项。`renderResources(data)` 调 `renderTemplate()`/`renderDownloads()` 填 `#template-list`/`#downloads-list`（下载卡片是 `<a class="template-item download-item">`，`href=/Downloads/<encodeURIComponent(file)>` + `download` 属性），`applyFilter()` 对两个子组**各自**判定可见性、全空才收起整块。
- **新增平台/板块要改的 key 列表不止四处**：六平台数组 `['atcoder','codeforces','nowcoder','hdu','xcpc','course']` 在 `app.js` 里硬编码了 **6 处** —— `findProblemUrl()` (29)、`applyStats()` (68)、`renderNav()` (110)、`render()` (223)、`findContestByDir()` (976)、`refreshData()` (1720)，另有 `applyFilter()` (194) 用一份**不同**的 8 项表（含 `luogu`/`resources`），`server.js` 的统计循环也有一次 (786)。漏掉 `findProblemUrl()` 或 `findContestByDir()` 会让新平台的深链静默失效。
- **比赛卡片点击 = 打开比赛信息小窗**（不再跳原站）：整卡 → `showContest(c)` 填 `#contestModal`（比赛名 + 状态徽标、进度 `x/y` + 百分比条、题目网格、目录路径；「打开原比赛 ↗」仅在有 url 时出现，⚙ 仅在 `--edit` 下出现；`total == null` 时只报已做题数、不编造百分比）。卡片上的题目 pill 行为不变（已做 → 代码小窗，未做 → 原题页面），小窗里的题目同理且用原生 `<button>`。空 url / 无 config 的情况用 `#ctNote` 一句话说明，不要静默隐藏按钮。LuoGu 章节树不走小窗（不是比赛）。卡片右侧（题目 pill 与状态标签之后）依次是：`↗` = 指向 `c.url` 的外链 `<a class="ext-link" target="_blank" rel="noopener">`（新标签打开原站，`stopPropagation` 不冒泡开小窗）、`❗` = 无 `.config.json` 时不可点的 `<span class="no-config-tag">`（有 config 但 url 为空则放不可见占位保持对齐）、`详情` = 本页打开小窗（见下一条）。
- **深链（可直接访问/分享）**：`?contest=<dir>` 直达比赛详情页，`?dir=<dir>&problem=<id>` 直达某题代码预览，两者可并列（`?contest=…&dir=…&problem=…`，刷新能同时还原两层）。URL 由 `writeShareUrl()` 统一改写（比赛态看 `ctDir`，代码态看 `codeShare`），逐层回落：关代码窗 → 保留 `contest` 再写回，关小窗 → 清空；`openFromUrl()` 先开比赛小窗再开代码小窗。卡片上那个「详情」`<a>`（`href="?contest=<dir>"`）就是这条链接的入口：**普通左键在本页无刷新开小窗**（`preventDefault()` + `showContest(c)`），href 保留以便右键复制 / Ctrl+点击 / 中键走浏览器原生新标签。改这段时注意：handler 必须**先无条件 `stopPropagation()`**，否则 Ctrl/Cmd+点击会冒泡到整卡 →「既开新标签又开小窗」（这个 bug 实际发生过）。
- **小窗层级与关闭顺序**：`#contestModal` 用基础 1000，其子窗口 `#codeModal`/`#cfgModal`/`#mkModal` = 1100，`#confirmModal` = 1200（改 modal 前先看这三条 CSS）。ESC 从最上层往下关：confirm → mk → cfg → code → contest。数据刷新（SSE / 保存 `.config.json`）后由 `syncContestView()` 按 `ctDir` 重绘小窗。
- **导航溢出（改 nav 前必读）**：`.container` 是 `max-width: 960px`，所以 `.nav-links` 的可用宽度**不随屏幕变宽而增大**（1440px 屏上也只有 754px）。8 项 + 搜索框在 ≥1024px 刚好放下（约 724px，余量 30px）；更窄就靠 `overflow-x: auto` 横滑，`updateNavOverflow()` 负责加 `.nav-links.is-overflowing`，由 CSS `mask-image` 让右端渐隐、提示可滑。**加任何 nav 项之前先量 `scrollWidth - clientWidth`**，否则末项会被无声裁掉（这正是「下载」项当初消失的原因）。

## Conventions

- **Naming**: bare stem only in contest dirs — `A.cpp` (letter platforms), `10.cpp` (HDU numeric), `P10446.cpp` (LuoGu IDs). LuoGu chapter files may embed the title after the ID.
- **Style A** (`#include <ihxnan>`, preferred for new solutions): header supplies everything above; write logic in `void solve()`, stdin → stdout. ~115 of the ~405 `.cpp` files (all the newer ones) carry the `acm` snippet banner — `#include <bits/stdc++.h>`, then `/* ──▶  INCLUDE  ◀── */` … `#include <ihxnan>` … `/* ──▶  /INCLUDE  ◀── */`, then `/* ╔══════════ SOLVE ══════════╗ */ void solve(){…} /* ╚══════════ /SOLVE ══════════╝ */`. The markers are cosmetic (nothing parses them); `inlineTemplates()` only rewrites `#include <x>` lines. Match whatever the sibling files in the target folder do — a few XCPC/HDU files instead open with plain `#include <bits/stdc++.h> #include <dbg> using namespace std; #define int long long`.
- **Style B** (legacy, 9 files: 6 in `LuoGu/算法竞赛进阶指南/`, 3 in HDU 联赛): self-contained `IO` struct with `fin`/`fout` and `#define cin fin`; use only when siblings in the folder use it.
- **对拍 / stress testing**: `data*.cpp` (uses `Generator`) + `ans.cpp`/`A.cpp` + a `diff_*.txt` output; scratch, kept alongside solutions, not cleaned up.
- New contest folder without `.config.json` → create `{"url": "…", "cnt": N}` with the round's real problem count.
- Python style: `from ihxnan import *` (展开自 `~/Github/Template/Template/ihxnan.py`) 提供 `I()`, `II()`, `MII()`, `LII()`, `GMI()`, `LGMI()` 及 `input = sys.stdin.readline` / `sys.setrecursionlimit(1000000)`；19/21 个 `.py` 这样写（唯一的例外是 `Template/md2pdf.py`）。有时整场比赛都用 Python（如 ABC 471 A–D、牛客周赛 Round 157 A–F）。
